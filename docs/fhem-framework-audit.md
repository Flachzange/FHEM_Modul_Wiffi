## Follow-up findings after the original framework audit (2026-10-14)

The audit missed an explicit installed-module version check, since its initial scope centered on lifecycle, FHEM APIs and runtime events. The implementation branch now contains **#18**: matching embedded semantic META versions for the collector/device and the standard `FHEM::Meta::InitMod`/`SetInternals` hooks for `FVERSION`. This follows the documented FHEM Meta mechanism for non-SVN modules; The original CI checked syntax, metadata parity and hook presence but **did not assert a populated FVERSION INTERNAL**. FHEM's real `FHEM::Meta::__CopyMetaToInternals` copies only `x_version`, which `__SetXVersion` fails to synthesize for a custom META.json version without SVN `$Id`. The work branch now falls back to `FHEM::Meta::Get($hash, 'version')` for a standard `FVERSION` INTERNAL if the framework did not set one; isolated instance tests assert the actual internal value. The corrected CI still does **not** replace an installed-FHEM confirmation. Verify that display with a short FHEM smoke check after installing the changed sources, without resurrecting waived comprehensive staging.

**#19** adds a separate `LAST_TELEGRAM` INTERNAL to both module types without Readings/DbLog/events. The collector's timestamp reflects valid decoded/identity-accepted reception (including unknown MACs and disabled logical devices); the device's timestamp reflects successful mapping/processing on an enabled logical device. `t/telegram_internals.t` checks both timestamps, unchanged sensor values, malformed frames, identity mismatch and disabled-device behavior with isolated FHEM callbacks. CI passes 10 test files / 988 tests; live FHEM display remains unverified.

**#20** was revisited after comparison with FHEM's own `MQTT2_DEVICE` (source blob `846d6dbfd64843ecd5583433592aeb3b5bc7de22`) and `MQTT2_SERVER` (blob `6203d044750faf121b5903197395c89ea003ea4d`). The work branch now uses native `IODev` for the single runtime collector binding, a MAC-only `DEF` for new and autocreated devices, and the optional collector-plus-MAC syntax for one-command explicit selection as well as backward compatibility. **New interactive manual definitions** call FHEM `CommandAttr` to persist `IODev` and canonicalize DEF to MAC-only, whether the collector was explicitly supplied or uniquely auto-selected. If more than one collector exists, MAC-only define is left unbound rather than choosing arbitrarily. Autocreate pins its source collector explicitly and persists `attr IODev`; **existing configurations restored during FHEM startup are not automatically rewritten** and remain migratable with explicit `attr IODev`, `modify <MAC>` and `save`. `AssignIoPort`'s core Reading side effects, startup association and rename/deleteattr behavior are accounted for. Isolated tests in `t/iodev.t` cover this design; a real FHEM/configDB smoke check remains unverified. No generic `IOWrite` or `Dispatch` machinery was introduced.

Reusable lessons were added to `AGENTS.md` and WIFFI-specific behavior to `AGENTS-WIFFI.md`. See the new issues for precise acceptance criteria; the original audit outcomes below remain a historical record of its earlier scope.

## Review conclusions and explicit non-changes

- **API and identity:** two canonical FHEM module filenames, `package main`, prefixed module callbacks, correct `DefFn`/`ReadFn`/`UndefFn`/`AttrFn` signatures and explicit shared helper loading. Exact `DefFn` arity was the only newly confirmed define-contract defect.
- **Lifecycle and ownership:** one TCP listener per collector, FHEM-owned temporary clients, explicit close/reopen/modify/disable handling and synchronous-notify identity checks. Existing retries/manual recovery are sufficient; no periodic reconnection manager or additional state registry was justified.
- **Events and state:** reading updates are the source of sensor truth. Successful asynchronous HTTP command dispatch must not imply physical state, including through FHEM's default synthetic `set` event. User-editable event/DbLog attributes and opt-in prefix handling remain unchanged.
- **Resource, input and security:** bounded frame/client lifetime and size, `allowfrom` FHEM source filter, MAC/IP identity conflicts, nonblocking HTTP, relative paths and no redirects. No speculative IP-age cutoff (closed #6) or diagnostic rate-limit/counter layer (closed #7).
- **Documentation and release:** Public usage examples use synthetic MAC addresses. FHEM-integrated bilingual help and separate release checklist exist. No SVN-only metadata requirements are imposed unless upstream inclusion is actually proposed. No version bump or release publication as part of this audit.
- **Remaining scope:** issue #4's implemented listener lifecycle and practical smoke tests were accepted; the comprehensive socket/disable scenarios were deliberately **not pursued**. The specific implementation tickets (#9 and transport/protocol tickets) are closed. Preserve the unverified assumptions in this report without promising deferred tests or opening duplicate defensive work. Colon-free MAC definitions (#11) are handled by the shared normalizer and covered by focused regression tests. Existing code fixes are not proof that all relevant staging tests were performed.
